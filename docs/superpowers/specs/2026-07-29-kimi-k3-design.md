## Контентная структура

1. **Хук** — открытый вес модель обгоняет закрытые флагманы в блайнд-тесте, это редкость, и повод спросить «как».

2. **Часть 1: Что внутри Kimi K3** — 2.8T параметров MoE, экстремальная разреженность (16 из 896 экспертов активны на токен, ~1.8%) — с кросс-ссылкой на [MoE-статью](/blog/moe-explained/), не пересказывая её механику заново, только новый факт («вот настолько разреженная конфигурация в проде»). 1M контекст, нативное зрение, always-on reasoning по умолчанию (в отличие от K2.5, где reasoning был опциональным — проверить этот контраст при написании). Бенчмарки: место на Arena Frontend Code Arena, сравнение с K2 (~2.5× эффективность скейлинга).

3. **Часть 2: Kimi Delta Attention** (основная техническая часть) — что такое гибрид линейного/полного внимания и зачем он нужен, с кросс-ссылками на уже опубликованные [KV-кэш](/blog/kv-cache/) и [FlashAttention](/blog/flashattention/) статьи (та же линия: decode упирается в память, не в FLOPs — KDA продолжает эту историю с другой стороны, снижая сам объём того, что нужно держать в памяти, а не то, как эффективно это читать). Разбор: слой Gated DeltaNet с более тонким гейтингом, гибридное соотношение KDA-к-полному-вниманию 3:1 по слоям, chunkwise-алгоритм поверх Diagonal-Plus-Low-Rank матриц перехода (концептуально, без полного матвывода), Attention Residuals для связи между слоями. Заявленный эффект: до 6× быстрее декодинг и ~75% экономии KV-кэша при сопоставимом качестве.

4. **Часть 3: Контекст и позиционирование** — K3 вышла через 2 дня после Qwen3.8-Max-Preview (Alibaba, 2.4T, «второе место после Fable 5» по собственному заявлению), на фоне DeepSeek V4 (V4 Pro/V4 Flash, тоже 1M контекст) — open-weight гонка обостряется, а не остывает.

5. **TL;DR**

### 1. Бенчмарк-сравнение
K3 vs Claude Fable 5/Opus 4.8, Qwen3.8-Max, DeepSeek V4 — аналог `KimiBenchmarkChart.tsx` из `kimi-k25.mdx` (переиспользовать паттерн, не обязательно код — данные другие). `client:visible`, реальные sourced цифры.

### 2. Full vs Linear vs Hybrid attention
Визуализация, почему гибрид 3:1 выигрывает по памяти/скорости на растущем контексте по сравнению с чистым full attention и чистым linear attention. Не прямой прецедент в блоге — концептуально близко к `TilingSimulator.tsx` (FlashAttention-статья) по духу «показать механику, не только цифры», но новый дизайн. Использовать заявленные из пейпера цифры (6×/75%), без фабрикации промежуточных точек, которые пейпер не даёт.

## Вне скоупа

- Полный математический вывод chunkwise-алгоритма Diagonal-Plus-Low-Rank — концептуальное объяснение, не построчный вывод формул.
- Собственные локальные бенчмарки/воспроизведение цифр — модель 2.8T параметров, локально не воспроизводимо; все количественные утверждения — с атрибуцией источника, без попытки самостоятельно измерить.
- Полный разбор AgentSwarmViz/KimiClaw-style бизнес-истории, как в K2.5 — если для K3 нет аналогичного отдельного бизнес-феномена (типа KimiClaw), не выдумывать его для симметрии со старой статьёй.
