# Статья: Токенизация — BPE и почему русский текст дороже

Дата: 2026-07-27

## Цель

Новая статья в блоге (категория «фундамент») про BPE-токенизацию: как строится словарь субслов и почему кириллический текст режется на в 1.5–2 раза больше токенов, чем эквивалентный английский — с живыми интерактивными демками, чтобы читатель проверил утверждения сам, а не поверил на слово.

Слаг: `tokenization`. Файл: `src/content/blog/tokenization.mdx`.

## Аудитория и голос

Та же аудитория и голос, что у остальных статей блога: практикующие AI/ML-инженеры, без воды, с кодом и конкретными цифрами, лёгкая ирония в духе «шизы» сайта.

## Контентная структура (черновой план разделов)

1. **Хук/TL;DR-заход** — почему это вообще важно (цена API считается по токенам, не по символам/словам).
2. **Что такое токенизация и зачем субслова** — коротко: почему не по словам (open vocabulary) и не по символам (слишком длинные последовательности).
3. **Как строится BPE-словарь** — механика мерджей на игрушечном корпусе → `BpeTrainerViz`.
4. **Живой токенизатор: разбираем текст по-настоящему** → `TokenizerPlayground` — плейграунд на реальном токенизаторе.
5. **Почему кириллица дороже** — механика: UTF-8 (кириллица 2 байта/символ vs 1 байт у латиницы) + англоцентричный корпус обучения токенизатора → меньше эффективных мерджей для русского. Подтверждается цифрами из плейграунда выше.
6. **Сравнение токенизаторов разных моделей** — статическая таблица (GPT-4o/o200k, GPT-4/cl100k, Claude, Qwen, DeepSeek) — примерные токенов-на-слово для русского/английского. Числа беру из публично известных оценок токенизаторов этих моделей (задокументировать источник во free-form тексте, не выдумывать точность, которой нет).
7. **Как посчитать самому** — код на Python (`tiktoken`) и JS (`gpt-tokenizer`) для подсчёта токенов и прикидки цены промпта.
8. **Что с этим делать на практике** — короткий практический вывод (закладывать больший token budget на русскоязычные промпты, не полагаться на «символы ≈ токены» при прикидке контекстного окна).
9. **TL;DR**.

Разделы 3–7 — это «много примеров», как просил пользователь; финальную формулировку и число под-примеров решаю по ходу написания, не жёстко фиксирую здесь.

## Интерактивные компоненты

### 1. `BpeTrainerViz.tsx`

- Пошаговый визуализатор обучения BPE на классическом игрушечном корпусе (`low`, `lower`, `lowest`, `newer`, `widest` — corpus из оригинальной статьи Sennrich et al. 2016).
- Показывает: текущее посимвольное представление слов → таблицу частот соседних пар → какая пара мерджится на этом шаге → обновлённое представление.
- Управление: кнопка «следующий шаг» (+ возможно «сброс»). Без client-side инференса, вся логика — небольшой детерминированный BPE-тренер на фиксированном корпусе, реализованный прямо в компоненте.
- `client:visible`, в стиле остальных «объясняющих механизм» вьюзов сайта (как `MoeExplorer`).

### 2. `TokenizerPlayground.tsx`

- Textarea для ввода произвольного текста + пресеты (минимум одна пара «одинаковое предложение на русском / на английском»).
- Библиотека: **`gpt-tokenizer`** (npm, pure JS, без WASM) — кодировки `cl100k_base` (GPT-4) и/или `o200k_base` (GPT-4o). Значит: реальная токенизация, не имитация.
- Вывод: раскрашенные чанки-токены инлайн (соседние токены — чередующиеся цвета), ховер/тап на токене показывает его id; счётчик токенов; для пресетной пары EN/RU — сравнение счётчиков и грубая оценка стоимости в $ по цене за 1M токенов (константа в коде, с пометкой что это ориентир, не точная цена конкретного тарифа).
- `client:visible`.

Оба компонента — новые файлы в `src/components/article/`, следуют существующим конвенциям каталога (аналог `MoeExplorer.tsx` / `KvCacheCalculator.tsx`): собственные инлайн-стили через CSS-переменные темы (`var(--accent)`, `var(--bg-card)` и т.д.), доступность (клавиатурная навигация там, где есть кликабельные элементы — паттерн `role="button"` + `tabIndex` + `onKeyDown`, уже отработанный в других компонентах сайта в этой сессии).

## Вне скоупа

- Живая токенизация для Claude/Qwen/DeepSeek — нет доступных лёгких JS-библиотек для браузера, эти токенизаторы идут только статическими цифрами в таблице.
- Полноценное обучение BPE на настоящем большом корпусе — визуализатор работает на игрушечном корпусе ради ясности объяснения, не ради реалистичного размера словаря.
